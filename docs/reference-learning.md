# Reference learning environment

Zlog now has an offline corpus path for studying finished edits before those observations become planner rules. It deliberately separates measured behavior, inferred style rules, renderer capability, and planner recommendations.

## What to send

Put references in `references/inbox/` with these constraints:

- One finished edit per file; keep the original audio track.
- `.mp4`, `.mov`, `.mkv`, or `.webm`; vertical and horizontal video are both accepted.
- Prefer 15 seconds to 10 minutes. Avoid compilation files containing unrelated creators or styles.
- Keep filenames stable and descriptive, for example `warm_cafe_dialogue_01.mp4`.
- Provide at least 5–10 references for each style cluster. A source-footage/final-edit pair is even more valuable when available; keep the pair names related and record the relationship in `notes` until pair fields are added.
- Only use material whose license permits this analysis. Record `license`, `source_url`, and `rights_holder` in a sidecar.

For facts the analyzer cannot safely infer, copy `references/annotations/_template.json` to either:

```text
references/annotations/warm_cafe_dialogue_01.mp4.json
```

or `warm_cafe_dialogue_01.json`. The exact filename form wins.

Preset IDs must come from `references/schemas/preset_registry.json`, generated by the init command. Unknown IDs and wrong categories fail validation instead of silently entering the dataset.

## Commands

```powershell
python -m pipeline.reference_learning init --root references
python -m pipeline.reference_learning analyze --root references
python -m pipeline.reference_learning analyze --root references --force
```

The first command writes current JSON Schemas and the versioned preset registry. The analyzer hashes each video for deduplication and a deterministic 80/10/10 train/validation/test split.

## Automatic versus manual evidence

Automatically measured:

- media duration, frame rate, dimensions, codec, hash, and audio-stream presence (`unknown` if ffprobe is unavailable);
- scene boundaries, cut density, shot-duration distribution, and a pacing label;
- sampled luminance, saturation, warmth proxy, and frame-change magnitude.

Manual annotation required:

- exact caption wording, placement, timing, and animation;
- whether visible motion is camera motion, subject motion, or an editorial transform;
- exact transition type, LUT/grade identity, overlay intent, beat sync, music ducking, and sound-effect intent;
- creative quality labels and licensing facts.

Frame change is never treated as proof of a push-in, tracking move, or handheld effect. Scene detection supplies boundary evidence but does not claim an exact transition preset.

## Artifacts

Each unique reference produces:

```text
references/library/<stem>-<sha10>/
  reference_analysis.json
  style_profile.json
  training_example.json
  debug.json
```

`training_example.json` is the canonical versioned record. It contains media metadata, observed edit analysis, a `StyleProfile`, optional current Zlog `EDL` target, quality labels, data split, provenance, and licensing. `style_profile.json` keeps four concepts separate:

- observed behavior from evidence;
- inferred reusable rules with confidence;
- planner recommendations using known preset IDs;
- hard constraints that prevent unsafe inference.

## Current boundary

This is the corpus and validation layer, not automatic imitation of a creator. It does not train model weights, extract copyrighted media from URLs, or pretend uncertain stylistic intent is known. The current Zlog `EDL` remains the deterministic renderer contract. The next vertical slice is to aggregate several compatible per-reference profiles into a named style profile and evaluate planner output against held-out references.
